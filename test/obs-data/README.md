# obs-data: the test estate's non-Lua asset trees

Everything a test package ships that is neither generated by `fklua mod` nor
compiled from Go. Today that is two locale files, one per data-stage-only
stand-in.

`fklua mod --include <dir>` merges a directory's CONTENTS into the package, so
each mod's tree is rooted here at its own name and holds `locale/` exactly as a
hand-written mod would. It is the test estate's equivalent of the shipped mod's
`mod-data/`, which `fklua.toml`'s `[mod] data` merges the same way; the test
packages have no manifest of their own, every identity of theirs being a Makefile
flag, so they reach it through `--include` instead.

A locale is the one thing neither a Go guest nor the packager can produce.
Factorio locale is `.cfg`, read by the engine at load, and no data-stage API can
emit one.

| directory | packaged as | what the file says |
|---|---|---|
| `belt-balancer-2/` | the `mig` suite's incumbent stand-in, under all four Belt Balancer names | `balancer-part=Balancer Part` |
| `bbb-mig-foreign/` | the same suite's stranger, who owns the same prototype name | the same |

**Both entries are the third-party mod's own English text, verbatim, and only
`en` is shipped.** This mod loads after any Belt Balancer, so an override with
different text would rename a working mod's entity in its own player's UI;
identical text makes the override a no-op, and shipping no other language leaves
every translation those mods have winning by fallback.

Nothing here is Lua. `agents/estate-port.md` is the programme that made that true
of the whole estate, and the guests these trees are packaged with are
`guest/go/obs/bb2data` and `guest/go/obs/foreigndata`.
