# The 200-byte localised-string ceiling

The long form of the critical rule CLAUDE.md states in one line.

**A SENTENCE THAT REACHES A DATA-STAGE PROTOTYPE'S `localised_description` MUST FIT 200 BYTES PER ELEMENT, and `make datastage-check`'s two `note` arms are what say the ones this mod can reach do.** On Factorio 2.0.77 build 84539 the engine refuses a localised-string element over 200 BYTES (not characters, and per element rather than per string) and stops the whole load, naming the offending element's 0-based index. **THE RULE IS A PROTOTYPE RULE AND NOT A WHOLE-MOD ONE**: a SETTING prototype is exempt, measured by FkRecipes at 201, 400, 1000, 2000 and 5000-byte elements all loading clean, which is why this mod's four composed setting descriptions are not chunked and are not what the note arms watch. **THIS BLOCKED 0.3.3 FROM RELEASE FROM 2026-09-14 UNTIL FkRecipes `137f4aa` ON THE SAME DAY, AND THE BLOCK IS LIFTED.** The library's own fallback sentence was 247 bytes with this mod's 39-byte setting name in it, so a typo a player typed into `better-belt-balancer-recipe-ingredients` STOPPED THE LOAD, and the `Error loading mods` dialog cannot reach the Mod Settings screen where it would be corrected; the unreleased 0.3.3 changelog and `README.md` both told a player the opposite, and neither was rewritten, because they described the release and the release was blocked. `137f4aa` chunks every literal the library composes into a PROTOTYPE's `localised_name` or `localised_description` at word boundaries into elements of at most 180 bytes, concatenation byte-identical, so that sentence comes out in TWO ELEMENTS cut at a word boundary. **MEASURED HERE ON THE SAME BINARY AT LIBRARY HEAD `61ac80c`**: that typo is exit 0 and a dump, `bbb-balancer-part.localised_description` is three elements whose concatenation is the 247-byte sentence byte for byte, and the recipe is the dropdown's own default, which is what a player who typed nothing gets. **BOTH NUMBERS IN THAT DATED ROW MOVED IN FkRecipes FIX ROUND 3 AND THE SHAPE WITH THEM**: `ca4c344` reworded the sentence to 268 bytes (229 of library constant plus this mod's 39-byte setting name), so the cut is 179 + 89 rather than 176 + 71, and `121aafc` opens the composition with the author's own `recipe-description` key in the engine's alternatives form, so the field is FOUR elements, the empty parameter and that key wrapper and the two chunks. The technology channel's note is 159 bytes and stays one piece. Measured at library head `cf66357` by `make datastage-check`'s `note-recipe` and `note-control` arms, which assert both chunk lengths and the key wrapper over what the engine put in the dump. **WHAT IS NOT MEASURED IS THE SCREEN.** The engine joins a localised string's parameters with nothing between them, so a chunk boundary SHOULD be invisible in a crafting tooltip, and nobody in either repository has hovered one: that is the client run owed since round three and it is the one thing not to take from these green rows. `test/check-datastage.py`'s `check_note_ceiling` is the standing guard, `note-recipe` and `note-control`, one per channel, each measuring every element against the ceiling over what the engine put in the dump. The whole finding is [`agents/fkrecipes-migration.md`](../fkrecipes-migration.md), "Fix round 2", fifth subsection, and the lift is "Fix round 2b re-adoption" after it.
